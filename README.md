# Forma

**A living design system. Designed and built by Lulamile Mkhungela.**

One token source, one shared language: the same 170 tokens drive the offline Figma plugin, the generated CSS and Sass, the React components, the Angular adapters and both Storybooks. Forest green, lime, and neutrals that stay out of the way.

I built Forma so design and code could stop translating each other. Nothing here is generated by a tool and left unreviewed — every token is hand-named, and the tests check that the pieces still point at each other.

## What one command builds in Figma

Import [`public/downloads/forma-figma-plugin.zip`](public/downloads/forma-figma-plugin.zip) into any file you control (**Plugins → Development → Import plugin from manifest**) and press **Build design library**. The plugin works offline — no API key, no account, no network — and creates:

- **170 native variables** in three collections: Primitives, Components, and Semantics with real **Light / Dark modes**.
- **Eight text styles** whose sizes are bound to `font.size` variables, so a token edit moves the style too.
- **16 component sets** — Button, Text field, Select, Checkbox, Radio group, Switch, Badge, Avatar, Card, Tabs, Accordion, Dialog, Alert, Progress, Tooltip, Table — with variants, auto layout, bound colours, radii and heights, and a `Label` property where it makes sense.
- **Four boards**: Start here, Foundations (every token drawn once), Components, and Patterns composed from real instances in both modes.

Re-running updates the Forma variables and adds fresh boards. Your own pages are never deleted, and the summary tells you exactly where everything landed.

## Start here

Node.js `22.12+`.

```bash
npm install
npm run workbench     # the guide on 5173 + React Storybook on 6006
```

| Command | What it does |
| --- | --- |
| `npm run workbench` | Guide and React Storybook together. |
| `npm run dev` | Just the guide. |
| `npm run tokens` | Rebuild CSS, Sass, Tokens Studio JSON, public downloads and the plugin's bundled tokens. |
| `npm run build:figma` | Type-check and bundle the plugin, mirror its sources, publish the live panel, repackage the ZIP. |
| `npm test` | 13 checks: tokens, exports, handoff map, offline manifest, ZIP bytes, plugin parity. |
| `npm run typecheck` | React components, stories and both copies of the plugin source. |
| `npm run build` | Tokens, type-check, production guide. |
| `npm run build-storybook` | Static React Storybook. |

Angular example:

```bash
cd examples/angular && npm install && npm start    # app on 4200, npm run storybook on 6007
```

## How the pieces stay aligned

- [`tokens/forma.tokens.json`](tokens/forma.tokens.json) is the only source. `npm run tokens` mirrors it to `public/tokens/`, `tokens/figma-tokens.json` (Tokens Studio) and `figma-plugin/forma.tokens.json`, so the plugin can never bundle a stale copy.
- [`figma-plugin/`](figma-plugin/) is the plugin project: `code.ts` is compiled to `code.js` and packaged into the ZIP. [`src/figma-plugin/`](src/figma-plugin/) is the same code mirrored so the repository type-check covers it. `npm test` fails if the two drift, if the ZIP differs from the project, or if a component description names a file that does not exist.
- The guide embeds the real plugin panel from `public/plugin/` — a live iframe, never a screenshot that could go stale. `npm run build:figma` keeps that copy byte-identical to `figma-plugin/ui.html`.
- Component descriptions written into Figma name the real handoff: the React export in [`src/system/components.tsx`](src/system/components.tsx), the Angular adapter in [`examples/angular/src/`](examples/angular/src/) (seven standalone `forma-*` components; the rest use semantic markup plus the shared CSS), and the matching Storybook story id.
- [`src/data/component-handoff.ts`](src/data/component-handoff.ts) is the map behind the guide's Components pages: Figma set, token paths, React export, Angular path, CSS selectors, story names and guideline anchor for all 16 sets.
- The React components consume the generated custom properties, so button heights, field heights, card padding, radii, border widths and focus rings are the token values — not lookalikes.
